# Markdown記法のお手本

このファイルは、記事を書くときによく使うMarkdown記法の見本です。必要な部分をコピーして使ってください。

> 記事のタイトルはfrontmatterの`title`から自動で表示されるので、本文では`# 見出し1`を使わず、`## 見出し2`から始めるのがおすすめです。

## Frontmatter（記事の設定）

ファイル先頭の`---`で囲まれた部分が、タイトルや公開日などの記事設定です。

```yaml
---
title: "記事のタイトル"
# 一覧の表紙だけ改行位置を指定したい場合（省略可）
# coverTitleLines:
#   - "表紙タイトルの1行目"
#   - "表紙タイトルの2行目"
description: "記事一覧や検索結果に表示する短い説明。"
publishedAt: 2026-08-30
updatedAt: 2026-09-01 # 更新したときだけ追加
category: daily # src/config.tsのCATEGORIESにあるキー
tags:
  - Astro
  - Markdown
draft: false # trueにすると公開されない
# cover: ./cover.jpg
# coverAlt: "表紙画像の説明"
---
```

表紙タイトルは、文字数と表示幅に応じて自動調整されます。自動改行が読みづらい記事だけ、`coverTitleLines`で一覧表紙と記事ページ見出しの区切りを指定できます。ブラウザのタブ、OGP、RSSなどで使う正式なタイトル文字列は`title`のままで変わりません。

`category`には、`src/config.ts`の`CATEGORIES`にあるキーを書きます。初期状態は`daily`（日常）、`tech`（技術）、`review`（感想）の3つです。

## 見出し

見出しは、文章のまとまりを分けるときに使います。

```markdown
## 大きな見出し

### 小さな見出し

#### さらに小さな見出し
```

見出しの直前と直後には空行を入れると、ファイルが読みやすくなります。

## 段落と改行

文章の間に空行を1行入れると、別の段落になります。

```markdown
これは1つ目の段落です。

これは2つ目の段落です。
```

同じ段落の途中でどうしても改行したい場合は、`<br />`を使えます。

```markdown
1行目。<br />
2行目。
```

通常の記事では、無理に改行せず段落で区切る方が読みやすくなります。

## 文字の強調

```markdown
**太字にしたい言葉**

_少し強調したい言葉_

~~取り消したい言葉~~

文章の途中に`コードやファイル名`を書く
```

表示例：**太字**、_斜体_、~~取り消し線~~、`src/content/blog/`

## リンク

```markdown
[Astroの公式サイト](https://astro.build/)
```

表示例：[Astroの公式サイト](https://astro.build/)

同じブログ内の記事へ移動する場合も、同じ書き方を使います。

```markdown
[記事一覧を見る](/posts/)
```

### リンクカード

外部ページをカードとして紹介したい場合は、URLだけを独立した1行に書きます。タイトル、説明、画像はリンク先からビルド時に自動取得されます。

```markdown
https://astro.build/
```

https://astro.build/

文章と同じ行にURLを書いた場合や、`[表示名](URL)`と書いた場合は、通常のテキストリンクになります。取得した結果は`src/data/link-cards.json`と`public/link-cards/`に保存されるので、コミットしておくと次回以降は再取得しません。リンク先の情報を取得できなかった場合は、ドメイン名を使った簡易カードとして表示します。

## 箇条書き

順番のないリストです。

```markdown
- ひとつ目
- ふたつ目
  - 入れ子の項目
  - もうひとつの項目
- みっつ目
```

- ひとつ目
- ふたつ目
  - 入れ子の項目
  - もうひとつの項目
- みっつ目

順番のあるリストです。

```markdown
1. Markdownを書く
2. ローカルで確認する
3. 公開する
```

1. Markdownを書く
2. ローカルで確認する
3. 公開する

チェックリストも使えます。

```markdown
- [x] 記事を書く
- [x] 読み直す
- [ ] 公開する
```

- [x] 記事を書く
- [x] 読み直す
- [ ] 公開する

## 引用

人の言葉や、本文から少し分けて見せたい文章に使います。

```markdown
> 引用する文章を書きます。
>
> 空の`>`を挟めば、引用の中で段落を分けられます。
```

> 引用する文章を書きます。
>
> 空の`>`を挟めば、引用の中で段落を分けられます。

引用元がある場合は、リンクも一緒に書いておくと親切です。

## キャラクターの吹き出し

引用の先頭行に`[!キー 表情]`を書くと、キャラクターの吹き出しとして表示されます。
キーは大文字と小文字を区別せず、表情を省略すると初期の表情になります。
キャラクターは`src/config.ts`の`CHARACTERS`で決めます。

```markdown
> [!NAGORI 通常]
> 吹き出しの中にも、段落やリンクを書けます。
```

`CHARACTERS`に登録していないキーは、通常の引用として表示されます。
登録済みのキーで未知の表情を書くと、ビルド時に警告が出て、通常の引用のままになります。
`CHARACTERS`を空にすると、この機能は使えなくなります。

## コード

短いコードやコマンドは、文章の途中でバッククォート1個を使います。

```markdown
`npm run dev`で開発サーバーを起動します。
```

複数行のコードは、バッククォート3個で囲みます。最初の行に言語名を書くと、色分けされます。

````markdown
```ts
const message: string = "hello";
console.log(message);
```
````

```ts
const message: string = "hello";
console.log(message);
```

よく使う言語名は、`js`、`ts`、`html`、`css`、`json`、`sh`、`text`などです。

## 画像

画像ファイルを記事の`index.md`と同じフォルダに置くと、相対パスで指定できます。

```text
src/content/blog/記事のフォルダ/
├── index.md
└── photo.jpg
```

```markdown
![写真の内容が分かる説明](./photo.jpg)
```

`[]`の中は、画像が見えない人にも内容が伝わる説明にします。装飾だけの画像なら空にできます。

```markdown
![](./decoration.png)
```

画像に説明文を添えたい場合は、画像の直後に普通の文章として書くのが簡単です。

## 表

情報を比較するときに使います。

```markdown
| 項目     | 内容           | 状態 |
| -------- | -------------- | ---- |
| 記事     | Markdownで管理 | 完了 |
| 検索     | Pagefindを使用 | 完了 |
| コメント | あとで考える   | 未定 |
```

| 項目     | 内容           | 状態 |
| -------- | -------------- | ---- |
| 記事     | Markdownで管理 | 完了 |
| 検索     | Pagefindを使用 | 完了 |
| コメント | あとで考える   | 未定 |

表はスマートフォンで横幅を取りやすいので、列を増やしすぎない方が安全です。

```markdown

```

## 脚注

本文の流れを止めずに補足を書きたいときに使えます。

```markdown
Astroは静的サイトの生成に対応しています。[^astro]

[^astro]: 補足説明や参照元をここに書きます。
```

Astroは静的サイトの生成に対応しています。[^astro]

[^astro]: 補足説明や参照元をここに書きます。

## 折りたたみ

長い補足やネタバレを隠したい場合は、HTMLの`details`を使えます。

```html
<details>
  <summary>補足を開く</summary>

  ここに隠しておきたい内容を書きます。
</details>
```

<details>
  <summary>補足を開く</summary>

ここに隠しておきたい内容を書きます。
</details>

## 記号をそのまま表示する

Markdownで意味を持つ記号をそのまま表示したいときは、直前にバックスラッシュを置きます。

```markdown
\*これは斜体になりません\*
\# これは見出しになりません
```

## コメント

公開ページには表示せず、自分用のメモだけをファイルに残せます。

```html
<!-- あとでこの段落を書き直す -->
```

## 書き終わったら

公開前に次のコマンドで表示とエラーを確認します。

```sh
npm run dev
```

ビルドまで確認する場合はこちらです。

```sh
npm run build
```

最後に、タイトル、説明、カテゴリー、リンク、画像の説明、`draft`の値を見直してください。
